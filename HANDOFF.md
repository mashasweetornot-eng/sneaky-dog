# Хэндофф: Sneaky Dog: Park Escape — версия 0.1.7

Ты принимаешь разработку мобильной игры **Sneaky Dog: Park Escape**. Ниже — фактическое состояние на момент передачи, что сделано в этой сессии, где лежит код, как его выкладывать и что осталось открытым. Не начинай проект заново: сначала изучи текущую сборку.

---

## 1. Идея и цель

Мобильная игра: игрок управляет собакой в парке. Цель — незаметно сделать «дело» на клумбе и вернуться к воротам. Садовник **охраняет клумбу** и ловит собаку; поимка — повтор уровня. Каждый уровень сложнее. Породы отличаются способностями (не скины). Тон — смешной, мультяшный, напряжённые погони.

Важно от пользователя:
- Это **мобильная игра**, а не браузерная. Текущий HTML — прототип для проверки геймплея на телефоне. Финальная форма (нативное приложение, 3D, движок) ещё не выбрана.
- Главная претензия, которая уже исправлена: садовник не должен «ходить просто так» — **его цель — контроль клумбы**.

Будущее визуальное направление (не начато): яркая мультяшная 3D, изометрическая камера 35–50°, видимый конус зрения; ориентиры — Untitled Goose Game, Sneaky Sasquatch, Crossy Road.

## 4. Технологии

HTML + CSS + обычный JavaScript, отрисовка Canvas 2D, интерфейс DOM, без библиотек, без сервера. Прогресс в `localStorage` под ключом `sneaky-dog-v1` (`{unlocked, best}`). Отладка: `window.SneakyDog.snapshot()` → `{state, level, dog, player, guards:[{x,y,state,idx,watch,angry,sus}], discovered, done, progress, elapsed, stamina}`; `window.SneakyDog.version`.

Основные части кода: `dogs`, `levelData`, `routeFor(i)` (расписание садовника), `makeMap()`, `blocked()/lineClear()/travel()`, `findPath()` (A*), `menu()/begin()/pause()/finish()`, `ability()`, `update(dt)`, `draw()`, `resize()`, `loop()`.

## 5. Что изменено в этой сессии (0.1.0 → 0.1.7)

### 0.1.1 — исправления прототипа
- Клавиша **C — красться** (скорость ×0.55, в кустах укрытие даже в движении; Shift при этом не работает).
- Клавиши по `e.code` — работают при **русской раскладке**.
- **Конус зрения** рисуется с реальной дальностью обнаружения (учёт породы, «Тихого шага», ярости).
- **Топот** при беге: радиус `NOISE = 165`, видимые круги, тост «Садовник услышал топот!», реагируют все не-преследующие садовники.
- Подсказки зависят от устройства (клавиатура/джойстик); «Слишком быстро» в кустах.
- Сброс `rings`, `noiseTimer`, `move` при перезапуске.
- Горизонтальный телефон: подсказки в боковые колонки; строка клавиш скрыта на сенсорных экранах; статус на ПК опущен вниз (раньше закрывал собаку).

### 0.1.2 — садовник охраняет клумбу (по запросу пользователя)
Садовник живёт по расписанию шагов `routeFor(i)`; шаг = `{x,y,wait,look,amp,sp,icon,bed}`:
- **Работа у клумбы** (💧) в точке `BED = (870,224)`: смотрит на клумбу, периодически оглядывается (качание взгляда `amp 1.25`). Пока он здесь — сделать дело нельзя.
- **Обход** (👀) — короткие остановки вокруг клумбы, взгляд наружу.
- **Дела** — кран 🚰 у `(230,182)` и тачка 🧺 у `(622,566)` (нарисованы на карте). Это окно для собаки.
- После мяча/шума/потерянной погони **возвращается прямо к клумбе** (первый шаг с `bed:true`).
- **«Сюрприз»**: если после дела садовник увидел клумбу → все садовники `angry` (скорость ×1.2, зрение ×1.15, 💢), нашедший бежит искать к воротам `(150,600)`.

Расписания:
- Парк 1: работа 6 с → кран 4 с (окно ≈ 18 с).
- Парк 2: работа 5 → обход ×2 → работа 4 → тачка 3.5 → работа 5 → обход → кран 3.5; зрение 228 — видит клумбу уже с дорожки.
- Парк 3: садовник 1 — работа/обход/кран/тачка; садовник 2 — ходит по подходам, смотрит на клумбу с `(763,335)` 2.2 с, тачка 2.5 с.

Проверено ботом: тактика «куст у клумбы → ждать ухода к крану → дело → бежать» проходит парк 1 (~21 с); стоять на клумбе при работе садовника — поимка; садовники не застревают.

### 0.1.3 — реакция на взгляд
- Любое попадание в зрение: садовник **останавливается и поворачивается к собаке** (`alertLook 0.7 с`), показывает «?» и шкалу.
- Потерял из вида при подозрении > 0.12 → идёт **проверять место** (inspect), тост «Садовник что-то заметил и идёт проверить».
- Подозрение растёт быстрее вблизи: `0.8 + 1.3·(1 − d/vis)` в секунду.
- iPhone: отключены выделение текста и меню при долгом нажатии.

### 0.1.4 — горизонтальный телефон и способность на ходу
- В горизонтали (высота < 560): камера следит за собакой, `scale = screenH/470`, камера может уезжать за края карты (`sideL 150px`, `sideR 180px`), чтобы ворота/клумба не прятались под джойстиком и кнопками; стрелка к цели вне экрана.
- Кнопка способности срабатывает по `pointerdown` (iOS не давал `click` при удержании джойстика). Проверено мультитач-эмуляцией.

### 0.1.5 — полный экран
- Кнопка ⛶ (Fullscreen API) — появляется только там, где браузер разрешает (ПК, Android, iPad; на iPhone её нет — Safari не даёт).
- Метатеги для режима «иконка на экране Домой» (`apple-mobile-web-app-capable`, `black-translucent`), apple-touch-icon, manifest, отступы под вырез экрана по бокам.

### 0.1.6–0.1.7 — сплющенная картинка на iPhone (в работе)
Симптом от пользователя: в горизонтали с иконки картинка **растянута по ширине ~2.2× и сплющена по высоте**, видна вся карта, собака под джойстиком. Вывод по скриншоту: битмап canvas почти квадратный, а растягивается CSS на экран 2.17:1 — то есть игра получала неверные размеры поля (вероятно, `canvas.clientHeight`/`100dvh` в standalone-режиме iOS после поворота).
- 0.1.6: каждый кадр сверять `canvas.clientWidth/Height` со `screenW/H` + `orientationchange` → **не помогло** (пользователь: «также сплющено»).
- **0.1.7 (сейчас)**: `resize()` берёт размер из `visualViewport.height || innerHeight` и ширины `#app`, **явно задаёт** `#app.style.height`, `canvas.style.width/height` в px и битмап; каждый кадр проверяет `innerWidth`/высоту вьюпорта; слушает `visualViewport.resize`. В меню паузы добавлена отладочная строка «Экран W×H · поле w×h».

**Ответа пользователя по 0.1.7 ещё нет.** Первое, что нужно сделать в новой сессии, — спросить, исправилось ли, и при необходимости попросить скриншот паузы с этой строкой.

## 7. Как выкладывать обновления (важно — ограничения окружения)

В этой сессии окружение Claude **не могло** пушить в GitHub напрямую:
- `gh`/REST привязаны к репозиториям, подключённым при запуске сессии; создание репо и запись настроек через API запрещены прокси.
- Создание публичного репо через браузер блокировал классификатор безопасности; публичным репо сделал Claude уже **по прямой просьбе пользователя**.
- Сеть контейнера не достаёт до `*.github.io` (проверять сайт — через встроенный браузер).

Рабочий способ, которым выкладывались 0.1.6–0.1.7 (встроенный браузер в приложении Claude, пользователь залогинен в GitHub):
1. Открыть `https://github.com/mashasweetornot-eng/sneaky-dog/edit/main/index.html`.
2. В JS страницы взять редактор: `const view=document.querySelector('.cm-content').cmTile.view;` и применить точечные замены через `view.dispatch({changes:[{from,to,insert}]})` (каждую строку искать `indexOf`, проверять уникальность; сверить итоговую длину с локальной в UTF-16).
3. Нажать «Commit changes...» → в диалоге «Commit changes».
4. Через ~30–60 с проверить `window.SneakyDog.version` на `https://mashasweetornot-eng.github.io/sneaky-dog/?v=<любое>`.

Новые бинарные файлы загружались через `/upload/main`: файлы собирались в странице из base64 и подставлялись в `input#upload-manifest-files-input` через `DataTransfer` (дорого по токенам — избегать).

**Лучше:** запускать новую сессию с подключённым репозиторием `mashasweetornot-eng/sneaky-dog` — тогда можно обычный `git push`.

Каждый раз также обновлять номер версии в двух местах: `Прототип 0.1.x` (меню) и `version:'0.1.x'`.
